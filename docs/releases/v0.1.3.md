# dsh-mcp v0.1.3 prerelease

This release repairs durable supervision around the Windows Guardian startup handshake and adds explicit, audited quarantine recovery. Missing startup IPC no longer loses the worker/helper identities. The helper persists suspended-child ownership before resuming and verifies an empty Job on both normal and exceptional completion. Native evidence writes support nested Windows state paths longer than 260 characters. Scheduler-to-Guardian integration tests exercise the final launch gate with local Node children.

Eight MCP tools include `dsh_quarantine_status` and evidence-verified `dsh_quarantine_release`. The CLI provides dry-run recovery and an explicit operator-attestation option for legacy records. Recovery preserves task history, original quarantine bytes and other unresolved incidents. Status/session/self-check queries do not recreate released quarantines or rewrite task state. Blocked submissions are checked before creating a scope.

Windows x64, bundled Node 24.19.0 and DSH Desktop 0.2.0-rc.2 are the qualified baseline. Existing v3 catalog, namespaces, native session IDs, task IDs and default workspace-write behavior are retained. The original incident's handshake timeout cause is still unknown.

Prepare and publish are separate Actions operations. Publish verifies the accepted source commit, artifact ID/digest, package fingerprint and ZIP SHA-256, and uploads the same runtime ZIP without rebuilding. `test-summary.json` is zero-model evidence. A separate `host-acceptance.json` binds one explicitly authorized read-only smoke task to this candidate. Its observed metrics may be null. This is not Russian semantic accuracy, audio production, broad model reliability, or cross-platform qualification. Historical paid-test results remain unchanged.

See `docs/public/upgrade-0.1.3.md`, `supervision-0.1.3.md` and `v0.1.3-verification.md` before upgrading.

## Credential environment correction

The bridge can explicitly fill named missing credential variables from the Windows User environment. Process-only inheritance remains the default; existing process values, including empty values, are preserved. Keys are not copied into client configuration, profiles, or task evidence. Diagnostics separate immutable profile integrity from credential presence and provider authorization. The default official route remains independent of the manual Desktop profile, with no automatic provider fallback.

Zero-model regressions cover environment precedence, safe lookup failures, non-persistence, real Guardian transit, and the shipped DSH credential resolver. An optional isolated resolver check accepts actual allowed environment references without loading an LLM adapter. This correction does not claim Russian semantic accuracy, provider authorization, or a new successful paid task without a candidate-bound acceptance receipt. The version remains 0.1.3; use artifact fingerprints to distinguish candidates.


## Completion-event relay correction (same-version reissue)

The bridge no longer settles on worker process exit while terminal IPC is still queued. It keeps IPC referenced and waits for the complete stdio/IPC close barrier before the runner flushes its parser and closes task logs. This removes the race that lost terminal `final` events and produced late `EBADF` writes after an exit-zero task had already failed. Explicit disconnect and tail callback errors are covered separately.

New zero-model regressions exercise controlled exit-before-tail ordering, real Guardian/runner short and long UTF-8 output, standalone IPC lifetime and the unchanged refusal to accept exit zero without `final`. No truncated progress fallback is added. Permission, process-tree proof, quarantine recovery and existing task history are preserved. The separate candidate-bound host acceptance receipt states the actual paid validation scope; this correction makes no Russian semantic accuracy or production-audio claim. Use the new manifest fingerprints, not version 0.1.3 alone, to identify this package.
