# dsh-mcp v0.1.4 prerelease changes

Implementation target: DSH Desktop **0.2.1-rc.2**, pinned source `687f282e8625c6b8d11ff58211a90524be2e4317`. This note describes the candidate changes, not an already published or paid-model-qualified artifact.

- Replace headless one-way task output with official SDK JSON-RPC over the existing supervised per-task process. Add guardian protocol 2 duplex input with bounded credit/backpressure; keep Job Objects, cancellation, total deadlines, empty-Job proof, IPC drain and quarantine.
- Use a new immutable base/sdk-app/official-Auto/question/bridge profile. Explicitly preserve launch-environment credential policy rather than importing GUI saved accounts. Default route stays deepseek-official / deepseek-flash.
- Expose reasoning off/low/high/max with native model-default resolution and no silent downgrade. Preserve complete provider/model rows when replacing native config.
- Expose read-only, workspace-write, auto and caller-context inherit. No direct Full access MCP option; native reviewed and single-use-approved Full access execution remains allowed. Auto loss closes new execution instead of accepting upstream's direct Full access fallback.
- Add dsh_capabilities, dsh_interactions and dsh_respond; eleven tools in total. Status includes waiting interactions and requested/effective configuration. Capability inventory distinguishes package availability, profile integrity, live verification and credential presence.
- Persist full native approval/question requests, digests, normalized submissions and native application ACKs separately. Add lossless details pagination and idempotent responses; retain the 64 KiB combined MCP budget.
- Support pause and timed-continue questions, native multi/custom answers and original plan-review intent. Retain continued questions after normal completion. Late answers explicitly create a same-session no-prompt SDK continuation when needed; queued intent is not delivery or permission, and may incur new model cost.
- Distinguish original project metadata from the effective working-directory projection. Revalidate native persistence before continuation. Keep managed state v3 additive and old records unchanged.
- Require fresh candidate/profile fingerprints and schema-v2 host acceptance. Separate submitted-task/continuation ledgers from observed agent and Auto-review model requests. Prepare/publish still promotes the exact accepted ZIP without rebuilding.

Legacy sandbox_mode read-only/workspace-write remains supported; combining it with permission_mode or requesting direct danger-full-access errors. The log spelling is not an alias for low. No runtime configuration hot switching, automatic crash replay, implicit profile bootstrap, provider fallback or Search/Fetch setup is added.

See [upgrade](../public/upgrade-0.1.4.md), [management API](../public/management-0.1.4.md) and [verification limits](../public/v0.1.4-verification.md). Real model acceptance, complete packaged-profile launch, persistent PTC kernel isolation and publication require separately scoped validation. Old receipts and paid ledgers are not reused.
