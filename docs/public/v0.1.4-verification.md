# v0.1.4 verification scope

## Identities and evidence boundaries

The implementation targets Windows x64, Node 24.19.0 and DSH Desktop 0.2.1-rc.2. The independent source reference is `687f282e8625c6b8d11ff58211a90524be2e4317`, compared against `639ed015397290b3745d163aafe02ffee4aa3f84`. The runtime checks the installed version, SDK identity and required native APIs; an inventory is not proof that an arbitrary distribution was built from that source commit.

The following checks are zero-model. No real provider stream, operator-home bootstrap, Desktop profile edit or release promotion is part of them. Local logs and temporary native history are not public release assets. Test summaries bind the actual source/runtime; source changes require another complete run.

## Unit and supervised-process regressions

`npm test` explicitly enumerates the existing suites plus SDK management, durable interaction and generic-MCP interaction suites. It covers:

- native-preset selection contracts, default/inherit mapping, unverified caller context, direct Full access input refusal, and allowed native reviewed/one-time-approved Full access;
- strict reasoning and whole-row overlay replacement without provider/model loss;
- fragmented Unicode NDJSON, malformed/error-null replies, request correlation, bounded guardian byte credit/backpressure, blocked-stdin cancellation and rejection of old guardian protocol;
- SDK initialization and total deadlines, successful new native turns, durable settlement, exit-zero/idle/old-event insufficiency, large UTF-8 completion and stdio/IPC close ordering;
- complete operation pages/digests, single/multi/custom answers and plan-review intent; duplicate/conflicting/stale/expired/cancelled/cross-task responses;
- queue versus native ACK, session-flush and submission/receipt write failures, post-queue expiry, continued questions, same-session no-prompt late answers and origin-failure races;
- read-only capability/status/interaction readers across reconnection, persisted continuation intent without a registered task, EOF/disconnection and quarantine preservation when final interaction writes fail;
- existing namespace/session serialization, workspace locks, process identity, recovery, launch credentials, public allowlists and exact-candidate promotion checks.

`npm run check:guardian` runs local Node child/descendant processes and a byte-exact duplex input/EOF fixture, then checks independent tree exit and owned-process liveness. Native builds retain safe staging and integrity-label/token preflight; no ACL or label bypass is a test remedy.

## Installed rc.2 contract

`npm run check:dsh-contract` loads the installed Cordis/session/agent-loop/SDK/persistence/permission/Auto/question/cwd modules in an isolated temporary DSH home. Local deterministic adapters synthesize agent and reviewer events. The real official adapter resolves its catalog/configuration only; it does not call stream, discover credentials over the network or request provider authorization.

The native cases cover three presets, initialize/resume/wait without a new prompt, cwd projection restoration, allowed/rejected/cancelled one-shot approval and unchanged standing preset, blocking questions, continued timeout and fresh-runtime native late-answer replay. They also exercise real PTC orchestration over a **synthetic substrate**, inner-call Auto review and inner-question ACK. Disposing official Auto demonstrates upstream's direct Full access fallback and the bridge's refusal to admit new work afterwards.

The real official/flash resolver is checked for off/low/high/max, its omitted default, and refusal of log. The bridge composition is checked for base + sdk-app, official Auto and disabled interactive credential rows. The optional `--credentials` flag checks named environment-reference presence/transit only, without emitting values. It does not validate CLI `.env` loading or a live credential.

**Limitations:** this is not a complete packaged immutable-profile CLI launch, a paid-model run, a production semantic corpus, or certification of persistent PTC subprocess/kernel isolation. Guardian process cleanup tests and a synthetic PTC runtime are separate evidence; do not conflate them. Live adapter/tool behavior, reviewer decisions, provider credit and full package launch remain candidate acceptance work.

## Package and acceptance

Source validation checks version 0.1.4, eleven MCP tools, public file/secret boundaries and release provenance fields: DSH baseline, source reference, profile generation, guardian protocol 2, SDK wire 0.0.1 and fixed runtime. A build requires clean committed source, the matching Node license, current native binary and same-source zero-model test attestation. Do not bypass those gates to produce a ZIP from an unfinished tree.

A published candidate needs a fresh schema-v2 host acceptance receipt with exact artifact/source/ZIP/profile identities, a task and continuation ledger, feature checks and independent tree/report/quarantine confirmation. Submitted tasks are not model requests. Model request counts remain null unless provider dispatch was actually observed; Auto requests are counted separately. The receipt is not automatically generated from unit success. Details: [release and acceptance](../release-and-acceptance.md).

A passing zero-model suite does not authorize a paid task, bootstrap, release, broad Full access reliability claim, audio workload or non-Windows qualification. Historical 0.1.1–0.1.3 records and the original 0/4 paid ledger are not revised by this update.
