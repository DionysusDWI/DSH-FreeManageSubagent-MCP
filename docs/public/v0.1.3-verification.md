# v0.1.3 verification boundaries

The candidate manifest identifies source commit, runtime, every packaged file and package fingerprint. The source commit must be clean. `test-summary.json` and its unit attestation cover zero-model tests only. CI also runs the real Windows Guardian with local Node processes, validates package hashes, and starts a copied package from an external directory with isolated state and bundled dependencies.

Regression cases include the scheduler calling its actual launch-authorization callback under the scope and registry locks, a real local Node child with v3 evidence paths longer than 260 characters, and a new quarantine appearing during preparation. They also cover durable preauthorization, fork/helper failure, state callback failure, real child execution with missing started IPC, handshake timeout, EOF, bridge/helper termination, cancellation, output drain, empty legacy PID sets, PID reuse, identity failures, multiple incidents, stale snapshots, partial recovery and idempotent completion. Queries are checked against file bytes, mtimes, scope and catalog revision. Fixtures use synthetic identities and temporary paths.

The installed DSH SDK contract is checked separately in a temporary isolated home without a model. Local deployment acceptance then verifies one submitted task: a fresh dedicated workspace/session, read-only sandbox, default provider/model, 120000 ms deadline, exact answer DSH_V013_SMOKE_OK, persisted main-agent permissions, report drain, confirmed tree exit and no new quarantine. Failed real-task acceptance is retained without automatic retries. Another candidate requires separate authorization for a new paid task.

The sanitized host receipt binds the accepted artifact's run ID, artifact ID and service digest to the source commit, package fingerprint and ZIP SHA-256. Submitted tasks equal one; model API call count is null because the bridge cannot independently measure all internal requests. Provider, model and usage are reported only when observable. The receipt also certifies an audited disposition of existing quarantines; full local incident evidence is excluded from public assets.

Publication checks the candidate's successful Actions run, workflow identity, commit, run attempt, immutable artifact identity and server digest. It verifies the annotated v0.1.3 tag and remote main, creates a draft, checks each uploaded asset's GitHub digest, and publishes the prerelease. It refuses tag/release/asset conflicts and preserves a draft on upload failure. Promotion performs no compilation or repackaging.

## Credential correction checks

Credential regressions cover process-only defaults, explicit Windows User allowlists, process/empty-value precedence, case folding, key rotation, missing/malformed/query failures, deadline-bounded hidden lookup, and value-free generated configuration and diagnostics. A runner fixture and real Windows Guardian verify synthetic credential transit without persistence or route changes. The isolated SDK contract checks the shipped credentials resolver with a synthetic launch-environment snapshot and confirms absence stays absent.

The optional `check-dsh-contract.js --credentials` operator check exercises actual allowed environment references through Guardian and installed Electron into the real resolver, using a temporary home without the operator credential store. It reports presence/source only and sends zero model requests. Neither this check nor profile integrity is a paid smoke pass or provider-authorization proof. A corrected same-version candidate still requires its own explicitly authorized host acceptance before publication; previous failed or differently fingerprinted candidates cannot supply it.


## Completion relay checks

Controlled worker fixtures deliver stdout, stderr, Guardian diagnostics and terminal exit IPC after worker process exit. Supervision must remain pending until the relay is closed; an original callback error must still reject. Other cases cover explicit disconnect without a combined close event and an IPC-referenced standalone process. Real Guardian/runner cases check short answers, lossless UTF-8 final output above 128 KiB and the unchanged failure for exit zero without `final`. All use local synthetic processes and send zero model requests. They do not use the business semantic corpus.

For a same-version reissue, preserve the previous release, annotated tag identity and asset checksums before any explicit operator archive operation. The publisher's tag/release conflict refusal remains enabled. Reissue does not reuse a previous candidate's host acceptance receipt.
