# v0.1.3 verification boundaries

The candidate manifest identifies source commit, runtime, every packaged file and package fingerprint. The source commit must be clean. `test-summary.json` and its unit attestation cover zero-model tests only. CI also runs the real Windows Guardian with local Node processes, validates package hashes, and starts a copied package from an external directory with isolated state and bundled dependencies.

Regression cases cover durable preauthorization, fork/helper failure, state callback failure, real child execution with missing started IPC, handshake timeout, EOF, bridge/helper termination, cancellation, output drain, empty legacy PID sets, PID reuse, identity failures, multiple incidents, stale snapshots, partial recovery and idempotent completion. Queries are checked against file bytes, mtimes, scope and catalog revision. Fixtures use synthetic identities and temporary paths.

The installed DSH SDK contract is checked separately in a temporary isolated home without a model. Local deployment acceptance then verifies one submitted task: a fresh dedicated workspace/session, read-only sandbox, default provider/model, 120000 ms deadline, exact answer DSH_V013_SMOKE_OK, persisted main-agent permissions, report drain, confirmed tree exit and no new quarantine. Failed real-task acceptance is retained without automatic retries. Another candidate requires separate authorization for a new paid task.

The sanitized host receipt binds the accepted artifact's run ID, artifact ID and service digest to the source commit, package fingerprint and ZIP SHA-256. Submitted tasks equal one; model API call count is null because the bridge cannot independently measure all internal requests. Provider, model and usage are reported only when observable. The receipt also certifies an audited disposition of existing quarantines; full local incident evidence is excluded from public assets.

Publication checks the candidate's successful Actions run, workflow identity, commit, run attempt, immutable artifact identity and server digest. It verifies the annotated v0.1.3 tag and remote main, creates a draft, checks each uploaded asset's GitHub digest, and publishes the prerelease. It refuses tag/release/asset conflicts and preserves a draft on upload failure. Promotion performs no compilation or repackaging.
